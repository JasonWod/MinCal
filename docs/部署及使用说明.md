# MinCal 部署及使用说明

> **极简团队日历工具**。Windows 桌面应用（托盘弹出 + 完整日历），**本地优先（local-first）**。
>
> **核心理念**：MinCal **默认是单机软件**——双击即用，日程存在你自己电脑上，**不需要联网、不需要注册、不需要服务器**。
> 只有在你想让 3–20 人团队共享日程时，才需要（可选地）部署一个自托管后端并连接，联网同步是**附加功能，不是前提**。

## 1. 两种使用模式

MinCal 可以单独用，也可以团队用，两者不冲突：

| 模式 | 需要后端？ | 数据存哪 | 适用场景 |
|------|-----------|---------|---------|
| **A. 单机**（默认） | ❌ 不需要 | 本机（浏览器内核 IndexedDB） | 个人日程管理、无需协作 |
| **B. 团队同步**（可选） | ✅ 需要 | 本机 + 自托管服务器双向同步 | 3–20 人共享日程、实时忙闲 |

```
┌─────────────────────────────────────────────────────────────┐
│  单机模式（默认，开箱即用）                                    │
│  MinCal.exe ──► 数据全在本机 IndexedDB，无需任何网络          │
└─────────────────────────────────────────────────────────────┘

┌─────────────────────────────────────────────────────────────┐
│  团队同步模式（可选，设置里连上服务器后开启）                    │
│  同事A 的 MinCal ◄──HTTPS/WSS──► 自托管服务器 ◄──► 同事B      │
│   (本机 IndexedDB)      (FastAPI + PostgreSQL)      (本机)   │
└─────────────────────────────────────────────────────────────┘
```

**要点：**
- 单机模式下，日程存本机，**断网/无网完全可用**，关机重启数据不丢。
- 切到团队模式后，本机仍是主存储，服务器做同步中枢；断网时改动存本机，恢复后自动同步，**不丢数据**。
- 服务器（若部署）完全在你自己的 Linux 机器上，数据不经过任何第三方云。

## 2. 客户端安装

客户端是 **Windows 桌面程序**（Tauri 打包的 `.exe`，约 2.6 MB 压缩包）。

### 方式 A：便携版（推荐，拿到就能用）

项目里已直接构建好一个 **Windows 便携 zip**（2026-10-26 重新构建，含权限/隐私修复 + 交互修复 + 端口变更）：

```
dist/MinCal-0.1.5-windows-x64.zip
  sha256: f943490e2c0a1c8aca1b3bd411bb42ea3417d6ad0c69f46607a1d27fede4bdc7
```

> **端口已整体更换**：服务器 `8091` → **`28091`**，客户端开发端口 `5173` → **`25173`**。
> 新端口都在系统临时端口区（32768–60999）**之外**，既不与本机其它服务冲突，也不会被随机占用。
> 旧客户端里存过的 `:8091` 会在启动时**自动改写**成 `:28091`，无需手动重填。
>
> **0.1.4 及更早的包请不要再用**：0.1.3 及更早是裸 `cargo build` 编出的**开发模式**产物
> （不读内嵌资源、去连开发服务器，双击报「拒绝连接」）；0.1.4 虽已是生产模式，但仍指向旧端口 8091。
> 生产模式请只看**内嵌资产清单**（exe 里有无 `assets/index-*.js`）——
> 注意 devUrl 端口串在 dev/prod 两种构建下都会被写进内嵌配置，**不能**拿它判断 dev/prod。
> exe 已用项目自签名证书签名（Issuer: `C=CN,O=MinCal,OU=MinCal Team,CN=MinCal`），验签通过。

**使用步骤：**
1. 把 zip 拷贝到任意一台 Windows 10/11 电脑（U 盘 / 局域网共享都行）。
2. **整个 zip 解压到一个文件夹**（例如 `D:\MinCal\`）。
3. 双击 `MinCal.exe` 即可运行。

> ⚠️ 解压后文件夹里应有 **6 个文件**，必须放一起，**不要只拷 `MinCal.exe`**：
> ```
> MinCal.exe                    主程序（双击运行，自签名）
> MicrosoftEdgeWebview2Setup.exe WebView2 运行库安装器（首次自动用；见下）
> WebView2Loader.dll            运行时依赖
> libunwind.dll                 运行时依赖
> MinCal证书.cer                自签名证书（双击安装可消除安全提示）
> 使用说明.txt                  使用须知
> ```

### 方式 B：从源码构建（进阶）

在**任意一台 Windows 10/11** 电脑上：
1. 安装 [Rust](https://rustup.rs) + [Node.js 18+](https://nodejs.org)
2. 把整个 `mincal` 文件夹拷到 Windows
3. PowerShell 运行：
   ```powershell
   cd mincal
   .\scripts\build-windows.ps1
   ```
   产出 NSIS 安装包 `client\src-tauri\target\release\bundle\nsis\MinCal Setup 0.1.5.exe`（双击安装，带开始菜单/桌面快捷方式）。

> ⚠️ **必须用 `npx tauri build`**（或裸 cargo 时显式 `--features custom-protocol`）。裸 `cargo build` 会产出**开发模式** exe，双击时报「localhost 拒绝连接」。

### 系统要求

- Windows 10 (1803+) 或 Windows 11
- WebView2 运行库：MinCal 用它渲染界面。**注意：不少 Windows 10/11 机器默认并没有装它**（没装的话双击 MinCal 会毫无反应）。本版 zip 已内置微软官方安装器 `MicrosoftEdgeWebview2Setup.exe`，**首次运行会自动联网装一次**（约 30 秒–2 分钟）；自动装不成时手动双击该文件即可。

## 3. 首次使用

> **不需要注册，不需要配服务器。**

1. **启动**：双击 `MinCal.exe`（便携版）或从开始菜单打开（安装包版）。
   **窗口会立即弹出**，直接进入日历界面，右上角状态显示「**本地**」。
2. **建个日程**：点右上角「＋」，或直接在日历某一天上点一下 → 填标题/时间 → 保存。
   日程立刻出现在日历上，并**自动保存在本机**，下次打开还在。
3. **设置个人信息**（可选）：点右上角 ⚙️ 齿轮，可改你的**显示名称、时区、专属颜色**。
   这些也全存本机。

**到此，单机使用已经完整可用。** 下面第 5 节的"团队同步"完全是可选的。

> **后台驻留**：关闭主窗口时程序缩到系统托盘（右下角），不会退出；右键托盘图标可「显示主窗口 / 打开弹出层 / 退出」。

## 4. 日常使用

### 4.1 快速看日程（最常用）

**点击右下角托盘的 MinCal 图标** → 弹出毛玻璃日历卡片：
- 显示今天 + 未来 2 天的日程
- 左侧 ◄ ► 切换日期
- （团队模式下）同事的忙碌时段显示为灰色条，看不到具体内容，保护隐私

### 4.2 快速新建日程

托盘卡片里点 **＋** → 填标题 + 选时间 + 选时长 → 创建。

### 4.3 编辑 / 删除

- 卡片/日历里**点**某条日程 → 打开编辑面板（改标题、时间、忙闲、颜色）
- 删除为软删除（团队模式下会同步给所有人）

### 4.4 完整日历视图

完整窗口支持 月 / 周 / 日 视图，适合做周计划或看多人叠加全景。

### 4.5 可见性控制（隐私）

| 级别 | 效果 |
|------|------|
| **忙碌**（默认） | 团队模式下别人只看到灰色"忙"块，看不到标题/内容 |
| **空闲** | 可被占用的空闲时段 |
| **公开** | 别人能看到完整信息 |

适合"开会想让大家知道我有事、但不想公开内容"——用**忙碌**即可。
（单机模式下可见性只是给自己的标记，不影响他人，因为别人看不到你的本机数据。）

### 4.6 同步状态（卡片/顶栏的状态点）

- ⚪ **灰「本地」** = 单机模式，数据只在本机（默认）
- 🟢 **绿「已同步」** = 已连服务器且同步正常
- 🟡 **黄「同步中」** = 正在拉取/推送
- 🔴 **红「离线」** = 连接服务器失败（断网/端口不通）——改动仍安全存在本机

### 4.7 设置（⚙️ 齿轮）

分两组：
- **本地偏好**（始终可用）：显示名称、时区、你的专属颜色。
- **服务器同步**（可选）：填服务器地址 → 注册/登录 → 连接。留空 = 纯单机。

## 5. （可选）团队联网同步部署

> **只在**你想让团队共享日程时才需要做这一节。纯单机用户可以直接跳过。

### 5.1 前置条件

- Linux 服务器（已在 Debian 13 验证），Docker + docker-compose
- 可用的 PostgreSQL（本项目用 `100.66.1.1:5432`）
- 项目代码已放到服务器（如 `~/projects/mincal`）

### 5.2 第一步：创建数据库

用超级用户（GoodsAdmin）连 PostgreSQL：

```bash
psql -h 100.66.1.1 -U GoodsAdmin -d postgres
```

```sql
CREATE USER mincal WITH PASSWORD '在这里设一个强密码';
CREATE DATABASE mincal OWNER mincal;
GRANT ALL PRIVILEGES ON DATABASE mincal TO mincal;
```

退出（`\q`）。密码记好，下一步要用。

### 5.3 第二步：配置（用 `.env`，**不要**把口令写进 docker-compose.yml）

真实配置已全部外置到项目根目录的 `.env`（已被 `.gitignore` 忽略，**不会进入 git 仓库**）：

```bash
cd ~/projects/mincal
cp .env.example .env
```

编辑 `.env`，填三项：

```bash
# ① 改成你 5.2 设的 PG 强密码
DATABASE_URL=postgresql+asyncpg://mincal:你的强密码@<PG主机>:5432/mincal

# ② 随机串（用下面的命令生成）
JWT_SECRET=<openssl rand -hex 32 的输出>

# ③ 客户端访问来源（按需加你的 LAN IP / 隧道 IP）
CORS_ORIGINS=http://localhost,http://127.0.0.1,http://<客户端IP>
```

生成随机 JWT_SECRET：
```bash
openssl rand -hex 32
```

> 🔒 **为什么这样设计**：`docker-compose.yml` 里只有 `${DATABASE_URL:?...}` 这类占位符。**漏填 `.env` 时 compose 会直接报错**（实测报 `required variable DATABASE_URL is missing a value`），既不会用默认口令悄悄启动，也不会把真实口令写进 git 历史。

> ⚠️ **端口检查**：本服务用 **28091** 端口。启动前确认没被占用：
> ```bash
> ss -tlnp | grep 28091
> ```
> 有冲突就改成别的空闲端口，并同步改客户端填的服务器地址。

### 5.4 第三步：构建并启动

```bash
cd ~/projects/mincal
docker-compose up -d --build
```

首次拉镜像 + 装依赖，需几分钟。

### 5.5 第四步：验证

```bash
curl http://127.0.0.1:28091/health     # 应返回 {"status":"ok","service":"mincal"}
docker logs mincal-server --tail 30   # 看到 SQLAlchemy 建表即成功
```

### 5.6 第五步：同事端连接（每台电脑做一次）

1. 打开 MinCal → 右上角 ⚙️ → **服务器同步**
2. **服务器地址**填：
   - 同局域网：`http://<服务器LAN IP>:28091`
   - 局域网外（走 NodeBabyLink 隧道）：`http://100.66.1.15:28091`
3. **创建账号**（首次）或 **登录**：用户名（唯一英文 ID）+ 密码 + 显示名称
4. 点 **连接** → 状态从「本地」变「已同步」✅

之后所有成员的日程自动双向同步、实时推送。

## 6. 故障排查

| 现象 | 原因 & 解决 |
|------|-----------|
| **双击 .exe 毫无反应**（无窗口、无托盘图标） | **最常见原因：这台机器没装 WebView2 运行库** → 双击 `MicrosoftEdgeWebview2Setup.exe` 装一次（约 30s–2min），再运行 MinCal。其次：① `WebView2Loader.dll`/`libunwind.dll` 是否与 exe 同目录；② 是否被 Defender 隔离（还原 + 加排除项）。仍不行：用记事本打开日志 `%LOCALAPPDATA%\MinCal\mincal.log`，把最后几行发我即可定位。 |
| 想彻底退出程序 | 右键托盘图标 → **退出 MinCal**（关主窗口只是隐藏到托盘，不退出） |
| 连服务器报 "Connection failed" | 服务器地址填错，或 28091 没起。先 `curl http://<服务器>:28091/health` |
| 状态一直 🔴 离线 | 网络/端口不通，查防火墙或隧道；**不影响本机使用**，改动存本机 |
| 改了日程同事看不到 | 在线时几秒内推；对方离线则下次打开/恢复网络时拉取 |
| 日历上是空的 | 确认新建了日程；或可见性设成"私有/忙碌"导致他人视角看不到（本人视角应能看到） |
| 时间对不上 | 设置里改时区；存储统一 UTC，显示按各自本地时区 |
| 杀软/SmartScreen 拦截 | Tauri 自签，加白名单或"仍要运行" |

## 7. 维护

### 更新版本
- **后端**（若部署）：改代码后 `docker-compose up -d --build` 重建
- **客户端**：重新构建新 zip / 安装包，发给同事**覆盖**旧的（注意保留同目录的 DLL）

### 备份
- **团队模式**：数据在 PostgreSQL 的 `mincal` 库，定期
  `pg_dump -h 100.66.1.1 -U GoodsAdmin mincal` 备份
- **单机模式**：数据在本机 WebView2/IndexedDB（`%APPDATA%` 附近），
  换机/重装前建议先导出（导出功能 v1.1 提供）；删该目录会清掉本机日程

### 常用运维命令

```bash
docker ps | grep mincal                                   # 服务状态
docker logs -f mincal-server                              # 实时日志
docker restart mincal-server                              # 重启
psql -h 100.66.1.1 -U mincal -d mincal \
  -c "SELECT count(*) FROM users; SELECT count(*) FROM events WHERE NOT deleted;"
```
